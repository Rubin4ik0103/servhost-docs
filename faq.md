# FAQ

## Перед началом

- Убедитесь, что доступна VNC или веб-консоль, и проверьте вход в неё.
- Сохраните резервную копию сетевого файла или профиля.
- Запишите текущие `ip a` и `ip route` (Windows: `Get-NetIPAddress` и `Get-NetRoute`).
- Не удаляйте основной IP. Выполняйте действия по одному.
- Настройка внутри ОС выполняется клиентом самостоятельно. Держите текущую SSH/RDP-сессию открытой и проверяйте новую сессию отдельно.

> Настройка сети может прервать удалённый доступ. Если нет работающей консоли, сначала обеспечьте её доступность.

**Почему IP есть в панели, но не работает?** Панель показывает назначение услуге. Проверьте добавление в ОС, маршрут, firewall и сервис по [диагностике](troubleshooting.md).

**Нужно ли менять основной IP?** Нет. Добавьте дополнительный на существующий интерфейс и сохраните основной адрес и маршрут.

**Можно ли удалить основной IP?** В рамках этой инструкции - нет: это может лишить вас доступа к серверу.

**Можно ли сделать дополнительный IP основным?** Простое добавление адреса не меняет основной IP услуги. Если нужна особая схема исходящего трафика, сначала уточните доступные параметры маршрутизации и настройте её отдельно.

**Почему новый IP не стал исходящим?** Система выбирает source IP по маршрутам и настройкам интерфейса; `curl -4 https://api.ipify.org` без указания source может показывать основной IP.

**Нужно ли менять gateway?** Обычно нет. Сохраните действующий default gateway. Новый gateway добавляйте лишь по явно предоставленной схеме сети.

**Почему после переустановки ОС всё пропало?** Переустановка удаляет данные и локальную сетевую конфигурацию. Добавьте IP заново в новой ОС.

**Можно ли настроить IP через VNC?** Да. Это предпочтительный способ безопасно применить изменения и восстановить доступ при ошибке.

**Почему на одном VPS IP появляется автоматически, а на другом нет?** Образы и менеджеры сети могут различаться. Проверьте фактические параметры в ОС, не ориентируйтесь только на панель.

**Что делать, если IP недоступен после корректной настройки?** Проверьте с другой сети, IP и prefix, route ответа, firewall и сервис. Соберите вывод по [диагностике](troubleshooting.md) и обратитесь в поддержку для проверки назначения и сетевой стороны. Не связывайте проблему с фильтрацией без отдельной диагностики.
